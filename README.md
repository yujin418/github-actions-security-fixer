# GitHub Actions 워크플로우 취약점 자동 수정 도구

GitHub Actions Workflow의 주요 보안 취약 패턴을 분석하고, AI 수정안과 변경 이유, 검증 결과를 GitHub Pull Request(PR)에 제공하는 도구입니다.

> 현재 개발 초기 단계이며, 아래 내용은 프로젝트의 목표 기능과 설계 방향을 설명합니다.

## 프로젝트 소개

GitHub Actions Workflow에는 실행 명령어, 저장소 접근 권한, 외부 Action 등 자동화 작업에 필요한 설정이 포함됩니다. 이러한 설정의 위험 요소를 점검하고, 개발자가 수정 내용을 이해하고 적용 여부를 판단할 수 있도록 돕는 것을 목표로 합니다.

프로젝트에서 말하는 ‘자동 수정’은 **수정안 생성과 제안까지**를 의미합니다. 수정 내용을 자동으로 병합하지 않으며, 사용자가 변경 내용과 검증 결과를 확인한 뒤 반영하도록 설계합니다.

## 주요 기능

- **취약 패턴 분석:** 규칙 기반으로 Workflow의 위험 설정과 문제 위치 탐지
- **AI 수정 제안:** 분석 결과를 바탕으로 수정안과 변경 이유 생성
- **수정안 검증:** 파일 형식 검사, 취약 패턴 재분석 및 테스트 환경에서 동작 확인
- **PR 결과 제공:** 분석 결과, 수정 전후 차이와 검증 결과 표시

기존 분석 도구를 활용하면서 **수정안이 대상 문제를 해소하고, 기존 Workflow의 기능을 유지하는지 확인하는 과정**에 중점을 둡니다.

## 분석 범위

`.github/workflows/` 내 YAML 파일을 대상으로 다음 세 가지 유형을 분석합니다.

| 유형 | 분석 내용 |
| --- | --- |
| **Script Injection** | 신뢰할 수 없는 입력이 실행 스크립트에 직접 삽입되는 패턴 |
| **Excessive GITHUB_TOKEN Permissions** | 작업에 필요한 범위보다 넓게 설정된 토큰 권한 |
| **Unpinned Actions** | 커밋 SHA로 고정되지 않은 외부 Action 참조 |

유형별 대표 패턴을 중심으로 탐지 조건과 수정 가능 조건을 구분합니다. 위험 설정이 탐지되더라도 수정에 필요한 정보가 부족한 경우에는 검토 대상으로 남기도록 설계합니다.

Pwn Request와 Artifact Trust는 실행 권한이나 Workflow 간 신뢰 관계 분석이 필요한 확장 대상입니다.

## 동작 흐름

```text
GitHub PR 이벤트
       ↓
Webhook 수신 및 요청 검증
       ↓
Workflow 파일 수집
       ↓
규칙 기반 취약 패턴 분석
       ↓
AI 수정안 및 변경 이유 생성
       ↓
수정안 검사 및 재분석
       ↓
PR에 수정 제안과 검증 결과 제공
```

### 규칙 기반 분석

Semgrep를 활용해 정의된 조건에 해당하는 취약 패턴을 탐지합니다. 분석 결과는 파일 경로, 문제 위치, 규칙 정보와 설명을 포함하는 공통 형식으로 정리합니다.

### 수정안 생성

Workflow와 탐지 결과를 LLM API에 전달하여 수정안과 변경 이유를 생성합니다. 수정 방식이 명확한 경우에는 규칙 기반 수정도 함께 검토하며, AI의 적용 범위는 비교 결과에 따라 조정합니다.

### 결과 제공

개발자가 변경 내용을 검토할 수 있도록 다음 정보를 GitHub PR에 제공합니다.

- 발견한 문제와 위치
- 수정 전후 차이
- 변경 이유
- 검증 결과와 추가 확인이 필요한 사항

## 수정안 검증

| 검증 항목 | 확인 내용 |
| --- | --- |
| **형식 및 설정 검사** | 수정된 YAML과 Workflow 설정의 유효성 |
| **취약점 재분석** | 수정 대상 패턴의 해소 여부 |
| **실행 테스트** | 테스트 저장소에서 기존 작업의 정상 동작 여부 |
| **변경 내용 확인** | 문제와 관계없는 불필요한 변경 여부 |

검증 결과는 통과·실패·미수행으로 구분합니다. 일부 검사 통과만으로 수정안 전체의 안전성을 보장하지 않으며, 확인하지 못한 항목도 함께 표시합니다.

실행 테스트는 비밀정보가 없는 개인 테스트 저장소를 기준으로 하며, 자동화 범위는 구현 과정에서 구체화합니다.

## 평가 기준

취약 예제와 정상 예제를 함께 사용하여 탐지와 수정 결과를 평가합니다.

- **탐지 결과:** 취약 패턴 탐지 여부, 오탐 및 미탐
- **수정 효과:** 대상 문제의 해소 여부
- **기능 유지:** 수정 후 기존 Workflow의 정상 동작 여부
- **변경 범위:** 불필요한 설정 변경 여부

기존 도구와 지원 범위가 겹치는 항목에는 동일한 예제를 적용합니다. 규칙 기반 수정과 AI 수정도 비교하여 각각 적합한 조건과 한계를 확인합니다. 기존 도구 대비 개선 여부는 이러한 평가 결과를 통해 판단합니다.

## 기술 구성

| 기술 | 역할 |
| --- | --- |
| **Python** | 백엔드 및 분석 로직 |
| **FastAPI** | Webhook 수신 및 API 구성 |
| **Semgrep** | 규칙 기반 Workflow 정적 분석 |
| **GitHub REST API / Webhooks** | 이벤트 수신, 파일 조회 및 결과 제공 |
| **LLM API** | 수정안과 변경 이유 생성 |

LLM 제공자와 모델, 의존성 버전 및 데이터 저장 방식은 구현 과정에서 결정합니다.

## 프로젝트 구조

```text
app/
├── __init__.py
├── main.py                 # 애플리케이션 진입점
├── webhook/                # 이벤트 수신 및 요청 검증
├── analyzer/               # Workflow 파싱 및 취약 패턴 분석
├── fixer/                  # 수정안과 변경 이유 생성
├── validator/              # 수정안 검증 및 재분석
├── github/                 # GitHub API 연동 및 결과 제공
└── database/               # 분석 결과 저장 — 도입 여부 미정
rules/                      # 보안 탐지 규칙
tests/                      # 테스트 코드 및 Workflow 예제
docs/                       # 학습 및 설계 문서
.github/workflows/          # 프로젝트 자체의 Workflow
requirements.txt            # Python 의존성 목록
.gitignore
README.md
```

기능별 모듈을 분리하여 탐지 규칙, 수정 방식 및 검증 항목을 확장할 수 있도록 구성합니다.

## 실행 안내

현재 실행 가능한 서버와 분석 명령은 제공하지 않습니다. 실행 기능이 마련되면 설치 방법, 환경 변수 및 사용 예제를 추가합니다.
