# 주차별 진행 워크플로우 (재사용 프롬프트)

매주 아래 프롬프트의 맨 위 `[이번 주차]` 3줄만 바꿔 사용한다.
순서: **구현·실행 → GitHub docs 정리·커밋 → 노션 산출물(표·개발정리·스터디) → 캡처 안내**.

---

```
[이번 주차] N주차 · 기간: __~__ · 이번 주 할 일(목표):
- (예: AI 수정안 생성 app/fixer 구현 / LLM 연동 / ...)

위 목표를 아래 순서로 진행해줘. 이 순서·형식을 매주 동일하게 유지해줘.

1) 시작 점검
- git 상태와 기존 변경사항을 먼저 확인해줘.
- 이번 작업으로 바꾼 파일만 커밋하고, 관련 없는 기존 변경은 포함하거나 되돌리지 마.

2) 구현 및 실행
- 위 목표 기능을 구현하고, 실제로 실행(pytest·CLI·uvicorn 등)해서 동작을 확인해줘.
- 실행 명령·환경·결과·오류를 기록하고, "확인한 사실"과 "추정"을 구분해줘.
- 비밀키나 외부 접근이 필요하면 임의로 만들지 말고 필요한 항목만 목록으로 정리해줘.
- 아직 실행·검증하지 않은 작업은 완료로 표시하지 마.

3) GitHub docs 정리 (주차 통일)
- docs/의 기존 주차 문서(week1~) 형식(번호형 섹션)을 그대로 따라 이번 주차 문서(docs/weekN-*.md)를 작성/통일해줘.
- 포함 항목: 이번 주 목표 / 구현한 것(파일 표) / 처리 흐름 / 설계 결정 / 겪은 문제와 해결 / 검증 결과 / (조사했으면)자료조사 / 한계·다음 단계 / 관련 문서·커밋.
- 기존 문서와 실제 코드가 다르면 코드·실행 결과를 근거로 표시하고, 중복 문서는 최소화해줘.
- 완료 / 시도했으나 실패·미완 / 제안만 / 미수행을 명확히 구분해줘.

4) 커밋 (내 이름)
- 작성자·커미터를 yujin418 / jeongyujin289@gmail.com 로 설정해줘. 전역 git 설정은 바꾸지 말고 이 저장소/커밋에만 적용.
- 기존 커밋 메시지 규칙(type: 설명, 예: feat:/docs:)을 따르고, AI 공동저자(Co-Authored-By) 줄은 넣지 마.
- 커밋 후 해시와 메시지를 알려줘. push는 내가 "push"라고 하면 해줘.

5) 노션용 산출물 (마지막에 복붙용 텍스트로만 제공, 직접 게시 금지)

(A) 주간 보고서 표 — 아래 틀 그대로 채워줘:
| 항목 | 내용 |
| 프로젝트 주제 | GitHub Actions 워크플로우 취약점 자동 수정 도구 개발 |
| 이번 주 목표 | |
| 진행 내용 | |
| 진행 결과 | |
| 문제점 및 이슈 | |
| 해결 방법 / 시도한 방법 | |
| 다음 주 계획 | |
| 기타 사항 | |

(B) 개발 정리 페이지 — 고정 틀:
· 속성: 카테고리 / 날짜(YYYY년 M월 D일) / 주차(N주차) / 진행 메모
· 본문(제목 = 이번 작업명): 작업 범위 → 오늘 구현한 것(파일|내용 표) → 설계 결정 → 구현 중 겪은 문제와 해결 → 검증 결과(코드블록) → 커밋 → 다음에 할 것

(C) 자료조사를 했으면 — 스터디 항목(공통 틀):
1. 목표 → 2. 수행 내용 → 3. 결과 및 확인 근거(조사 완료/구현 완료 구분, 미검증은 "확인 필요") → 4. 남은 작업 → 5. 관련 자료(조사일·출처 링크·사용 버전)

6) 첨부 캡처 안내
- 이번 주 활동 증명으로 어디를 캡처하면 좋은지(실행 명령 포함) 짚어줘.
```
